### NGSolve: Piecewise-Constant Right-Hand Sides and the FEM--Graph Connection

#### Piecewise-constant right-hand side in NGSolve

**User:** How can I have a piecewise constant function for the right
hand side in NGSolve such that each element gets one constant?

**Assistant:**

In NGSolve, a clean way is to put the right-hand side in the
discontinuous piecewise-constant space `L2(mesh, order=0)`. Each mesh
element then has exactly one degree of freedom, so each element can
receive its own independent constant.

``` python
from ngsolve import *
import numpy as np

# assuming you already have mesh
fes_rhs = L2(mesh, order=0)

f = GridFunction(fes_rhs)

# one random constant per element
for el in mesh.Elements(VOL):
    f.vec[fes_rhs.GetDofNrs(el)[0]] = np.random.randn()
```

Now `f` is constant on each element and can be used directly in a weak
form:

``` python
fes = H1(mesh, order=1, dirichlet=".*")
u, v = fes.TnT()

a = BilinearForm(fes)
a += grad(u) * grad(v) * dx

rhs = LinearForm(fes)
rhs += f * v * dx

a.Assemble()
rhs.Assemble()
```

Since `order=0` gives one DOF per element, for random values you can
usually assign the vector directly:

``` python
fes_rhs = L2(mesh, order=0)
f = GridFunction(fes_rhs)

f.vec.FV().NumPy()[:] = np.random.randn(fes_rhs.ndof)
```

You can inspect it with:

``` python
Draw(f, mesh, "piecewise constant rhs")
```

Mathematically, this constructs

$$
f(x)=f_K, \qquad x\in K,
$$

where every element $K$ gets its own scalar $f_K$. The discontinuous
$L^2$ finite-element space of order zero is

$$
V_h=\{v:v|_K\in\mathbb P_0(K)\text{ for every }K\in\mathcal T_h\}.
$$

Unlike an `H1` grid function, neighboring elements do not share DOFs, so
each element's value is independent.

If you want to retain the values explicitly for later restriction,
prolongation, or correlated random fields:

``` python
values = np.random.randn(fes_rhs.ndof)

f = GridFunction(fes_rhs)
f.vec.FV().NumPy()[:] = values
```

Then `values` is the elementwise random-field realization and `f` is its
NGSolve representation.

#### Finite elements and graphs

**User:** finite elements and graphs connection

**Assistant:**

There is a strong connection between finite elements and graphs. At the
simplest level:

> A finite-element mesh induces a graph, and the assembled FEM matrix is
> essentially a weighted graph operator on that graph.

##### 1. From a finite-element mesh to a graph

For standard continuous piecewise-linear ($P_1$) elements, put a graph
vertex at every FEM degree of freedom:

$$
V=\{1,\ldots,N\}.
$$

Connect vertices $i$ and $j$ whenever their basis functions overlap:

$$
(i,j)\in E
\quad\Longleftrightarrow\quad
\operatorname{supp}(\phi_i)\cap\operatorname{supp}(\phi_j)\neq\varnothing.
$$

Equivalently, for a typical assembled FEM matrix $A$,

$$
(i,j)\in E
\quad\Longleftrightarrow\quad
A_{ij}\neq0,\qquad i\neq j.
$$

Thus the sparsity pattern of $A$ gives the FEM graph.

##### 2. Why this happens naturally

For Poisson's equation,

$$
-\nabla\cdot(\kappa\nabla u)=f,
$$

the FEM stiffness matrix is

$$
A_{ij}=\int_\Omega \kappa(x)\,\nabla\phi_i(x)\cdot\nabla\phi_j(x)\,dx.
$$

If $\phi_i$ and $\phi_j$ do not overlap, the integral is zero. Therefore
$A_{ij}\neq0$ only when DOFs $i$ and $j$ interact locally in the mesh.
This is exactly the information represented by graph adjacency.

##### 3. The stiffness matrix and graph Laplacian

A weighted graph Laplacian has the form

$$
L=D-W,
$$

where $W$ contains edge weights and

$$
D_{ii}=\sum_j W_{ij}.
$$

For diffusion problems, the FEM stiffness matrix behaves much like a
weighted graph Laplacian.

For a graph Laplacian,

$$
x^TLx=\frac12\sum_{i,j}w_{ij}(x_i-x_j)^2.
$$

For FEM,

$$
x^TAx=\int_\Omega \kappa(x)\left|\nabla\left(\sum_i x_i\phi_i\right)\right|^2dx.
$$

Both measure how rapidly a quantity changes between neighboring parts of
the domain. Small energy corresponds to neighboring DOFs having similar
values; large energy corresponds to strong variation.

##### 4. Several graphs can be associated with one FEM problem

For nodal $P_1$ FEM, the obvious graph is the **DOF graph**:

$$
\text{node/DOF}\longleftrightarrow\text{graph vertex}.
$$

You can instead construct an **element adjacency graph**:

$$
\text{finite element}\longleftrightarrow\text{graph vertex},
$$

with $K_i\sim K_j$ when elements $K_i$ and $K_j$ share a face or edge.

For the `L2(mesh, order=0)` function above,

$$
f|_{K_i}=f_i,
$$

so the vector

$$
\mathbf f=\begin{bmatrix}f_1\\f_2\\\vdots\\f_{N_e}\end{bmatrix}
$$

can be viewed literally as a signal on the vertices of the element
graph.

This viewpoint is useful for constructing spatially correlated random
element values. For example, if $L_E$ is an element-graph Laplacian, one
might define

$$
Q=\tau^2(\kappa^2I+L_E)^\alpha
$$

as a precision operator for a Gaussian random field on the elements.
This connects FEM, Gaussian random fields, GMRFs, SPDEs, and graph
models.

##### 5. FEM assembly can be viewed graphically

Each element has a local stiffness matrix $A^{(K)}$. Assembly inserts
these local interactions into the global graph:

$$
A=\sum_K R_K^T A^{(K)}R_K,
$$

where $R_K$ maps global DOFs to the DOFs belonging to element $K$.

Every element therefore contributes a small clique of interactions to
the global graph. For a $P_1$ triangular element with nodes $i,j,k$, the
element contributes interactions among

$$
(i,j),\qquad(i,k),\qquad(j,k).
$$

##### 6. Connection to multilevel methods

This is a bridge from geometric multigrid to algebraic multigrid.

In geometric multigrid, the mesh hierarchy is known:

$$
\mathcal T_0\rightarrow\mathcal T_1\rightarrow\mathcal T_2\rightarrow\cdots
$$

and its geometry is used to construct coarse spaces.

In algebraic multigrid, much of the construction can instead be based on
the assembled matrix $A$. Its sparsity and coefficient structure define
a weighted graph $G(A)$. AMG then asks questions such as:

-   Which graph vertices are strongly connected?
-   Which vertices should become coarse DOFs?
-   Which fine vertices should interpolate from which coarse vertices?
-   Which groups of vertices should form aggregates?

Conceptually,

$$
\boxed{\text{PDE}\rightarrow\text{mesh}\rightarrow\text{finite-element space}\rightarrow A\rightarrow G(A)}.
$$

After the last step, much of the solver construction can be performed
using graph algorithms rather than geometric algorithms.

This is also related to AMGe, where element information is retained and
exploited rather than treating the assembled matrix as the only
available object.

##### 7. Matrices worth distinguishing

Several matrices can look graph-like but represent different things:

  Matrix      Meaning
  ----------- ---------------------------
  $B$         graph incidence matrix
  $W$         weighted adjacency matrix
  $L=B^TWB$   graph Laplacian
  $M$         FEM mass matrix
  $A$         FEM stiffness matrix

They are not generally interchangeable, but there are deep
correspondences. In particular, $B^TWB$ and the FEM stiffness operator
both arise from measuring differences or derivatives and forming an
energy from those differences.

This viewpoint becomes even richer with discrete exterior calculus and
higher-order FEM: vertices, edges, faces, and cells form a combinatorial
complex, and incidence matrices act like discrete versions of gradient,
curl, and divergence.

For NGSolve work, it can be useful to distinguish three graph
representations:

1.  **DOF graph** from the stiffness matrix.
2.  **Element adjacency graph** from the mesh.
3.  **Bipartite DOF--element graph**, with one node type for elements
    and another for FEM DOFs, and edges encoding which DOFs belong to
    which elements.

The bipartite representation preserves substantially more FEM structure
than simply converting `a.mat` into an adjacency matrix.
